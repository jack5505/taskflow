# web/ — веб-интерфейс

Общие правила — в корневом `CLAUDE.md`. Здесь — то, что касается фронтенда.

## Стек и команды

React 18, TypeScript, Vite, TanStack Query, dnd-kit для перетаскивания. Линтеры — oxlint (TS) и stylelint (CSS).

```
npm ci            установка
npm run dev       Vite, /api проксируется на localhost:8100
npm run lint      oxlint и stylelint (оба, даже если первый упал)
npm test          Vitest (юнит-тесты, *.test.ts рядом с кодом)
npm run e2e       Playwright (e2e/*.e2e.ts) против стенда из e2e/stack.sh
npm run build     tsc -b && vite build → ../api/internal/web/dist (встраивается в бинарник Go)
```

Сборка пишет в `api/internal/web/dist`; в git там только заглушка `index.html`, остальное игнорируется.

## Правила

- Экраны — по ТЗ §7 (восемь экранов) и ничего сверх: вход (и страница ссылки-приглашения `/join/<токен>`, §7.1), проекты с «Моими задачами», доска, бэклог и спринты, карточка задачи, отчёты, профиль, настройки проекта с шестью вкладками и седьмой «GitHub», когда интеграция подключена (§12.1).
- Запросы к API — только через сгенерированный из Swagger клиент (issue #4), не через ручные `fetch`. Состояние сервера — TanStack Query; глобальный стор не заводить.
- Авторизация: access-токен в памяти, refresh в httpOnly cookie, автообновление по 401 (§9.1). Токен в localStorage не хранить.
- Права из §2 дублируются в интерфейсе только для скрытия кнопок; настоящая проверка — на сервере. Кнопка, которую сервер отклонит, не показывается.
- Markdown (описание, комментарии) рендерить с санитайзингом, сырой HTML запрещён (§10.3).
- Даты показывать как `dd.mm.yyyy`, время — в поясе пользователя из профиля (§7). Длительности — в формате `2h 30m` (§6.1).
- Фильтры доски хранятся в URL (§7.3): перезагрузка страницы их не теряет.
- При `409 VERSION_CONFLICT` показывать чужие правки и предлагать повторить, не перезаписывать молча (§3.3).
- Язык интерфейса только русский (§10.3); тексты без зависимости от рода пользователя.
- Адаптивно от 360 px (§7, §11 п. 14): телефонная раскладка — один блок `@media (width < 768px)` в конце `index.css`; страница не прокручивается по горизонтали, широкое (таблицы, колонки доски) прокручивается внутри своего блока. Проверка — `e2e/mobile.e2e.ts` на 375 px. Перетаскивание — `useDragSensors` (мышь, долгое нажатие пальцем, клавиатура).
- CSS — плоский, без вложенных правил: stylelint запрещает вложенность (`max-nesting-depth: 0`), потому что потерянная `}` превращает следующие правила во вложенные и браузер их молча не применяет (#174). Цвета — через переменные в `:root`. `no-descending-specificity` выключен: стили построены на каскаде «общее → частное».

## Тесты

Vitest для логики (парсеры, форматирование), Playwright для сценариев приёмки из §10.4 (issue #46) — job `E2E (Playwright)` в CI.

- Стенд: `e2e/stack.sh up` собирает образ и поднимает api, worker, postgres, redis отдельным compose-проектом (`E2E_PROJECT`, по умолчанию `taskflow-e2e`, порт `E2E_PORT`, по умолчанию 8199), создаёт администраторов командой `taskflow admin create` и печатает `E2E_*=…` для тестов. `e2e/stack.sh down` удаляет всё вместе с данными. Ссылки одноразовые: сценарий входа проходит один раз на стенд — для повторного прогона стенд пересоздают.
- Данные каждый сценарий готовит сам через API (`e2e/fixtures.ts`, свой проект со случайным ключом); через интерфейс — только проверяемое действие. Ожидания — `expect(...)` и `expect.poll`, без `waitForTimeout`.
- Локально Chromium на сервере не стартует — запускать в образе той же версии, что `@playwright/test`:
  `E2E_PORT=8199 e2e/stack.sh up > /tmp/e2e.env && docker run --rm --network host --ipc=host -u $(id -u) -e HOME=/tmp --env-file /tmp/e2e.env -v $PWD:/web -w /web mcr.microsoft.com/playwright:v1.63.0-noble npx playwright test` (нужен `npm ci`), затем `e2e/stack.sh down`.
