# api/ — серверная часть на Go

Общие правила — в корневом `CLAUDE.md`. Здесь — то, что касается Go-кода.

## Структура

```
cmd/taskflow/        точка входа; режимы api | worker | admin
internal/config/     настройки из env; новая переменная → сюда и в .env.example
internal/httpserver/ Gin: роутер, middleware (request_id, лог), статика SPA
internal/web/        embed собранного фронтенда (dist/index.html — заглушка в git)
migrations/          SQL golang-migrate: YYYYMMDDHHMMSS_name.{up,down}.sql
```

Домены добавляются как `internal/<домен>/` по сущностям ТЗ §3: `user`, `project`, `task`, `sprint`, `worklog`, `telegram`, `notification`. Внутри домена: модель, репозиторий (GORM), сервис (правила ТЗ), HTTP-обработчики. Правила ТЗ живут в сервисе, а не в обработчике и не в репозитории — бот вызывает сервис напрямую.

## Владение таблицами

Каждая таблица принадлежит ровно одному модулю (пакету `internal/<модуль>`). SQL к ней пишет только владелец; остальные модули вызывают его экспортированные функции (`task.FreeInSprints(...)`, `project.ChatProjects(...)`), которые возвращают доменные структуры и уже применяют общие правила видимости: удалённая задача не видна, архивный проект, не участник — 404.

| Модуль | Таблицы |
| --- | --- |
| `user` | `users` |
| `auth` | `refresh_tokens`, `password_tokens` |
| `project` | `projects`, `project_members` |
| `task` | `tasks`, `task_history`, `comments`, `attachments`, `worklogs`, `active_timers`, `github_links` |
| `sprint` | `sprints`, `sprint_log`, `sprint_start_scope`, `sprint_daily_snapshots` |
| `notification` | `notifications`, `due_reminders` |
| `telegram` | `one_time_codes`, `daily_summaries` |
| `audit` | `audit_logs` |
| `github` | `github_deliveries` |
| `outbox` | `outbox_events` (запись события в транзакции — общий API `events.Add`, модель `events.OutboxEvent`) |

- **Внутри модуля два слоя.** `store.go` (или `store_*.go`) — только запросы: функции названы по смыслу (`lockTask`, `daySum`, `freeTasksOfSprint`), принимают `*gorm.DB` или транзакцию, бизнес-правил не содержат. Сервис — правила ТЗ, права, транзакции, события и порядок блокировок; порядок блокировок остаётся явным в сервисе, не прячется в универсальный DAO.
- **Чужая транзакция.** Функция модуля, которую вызывают внутри транзакции другого модуля, принимает `tx *gorm.DB` и в комментарии пишет, какие строки блокирует и в каком порядке (как `openTask`, `StopUserTimer`).
- **Постоянные исключения:** `report` (агрегирующие отчёты одним запросом ради производительности §10.3) и `loadgen` (генератор тестовых данных) читают таблицы напрямую. Другое исключение — только правкой этого списка и `readAnyTable` в архитектурном тесте.
- **Проверка.** `internal/archtest` разбирает не-тестовые Go-файлы и считает обращения к чужим таблицам: в строковых литералах, похожих на SQL, — после `FROM` (включая списки `FROM a x, b y`), `JOIN`, `UPDATE`, `INTO`, `TRUNCATE`, `LOCK`, а также в `.Table("…")`. Таблица без владельца в миграциях роняет тест: новая таблица → строка в таблице выше и в `owners` теста. Не проверяются `docs` (сгенерированный Swagger) и `testutil` (фикстуры тестов); пакет `events` считается частью модуля `outbox`.
- **Запросы только в слое запросов.** `TestSQLOnlyInStore` считает запросы в не-тестовых файлах модулей-владельцев и доменных сервисов `me`, `users` вне `store.go`, `store_*.go` и пакетов запросов `sprint/sprintdb`, `task/taskdb`: строки — запросы целиком (начинаются с `SELECT`, `INSERT INTO`, `UPDATE … SET`, `DELETE FROM`, `WITH … AS (`, `TRUNCATE`, `LOCK TABLE`, в том числе после комментария `--` и скобки), вызовы `.Table("…")` и чтения цепочкой GORM (`Pluck`, `Find`, `First`). Записи через модель (`Create`, `Model(…).Updates`, `Delete`) правило не считает. Временный список `internal/archtest/temporary_sql_outside_store.txt` («файл число») пуст с #145 — новые строки не добавляются.
- **Временные нарушения владения** — `internal/archtest/temporary_violations.txt` (пуст с #144), строки «файл таблица число_обращений». Список только сокращается: новое обращение в уже записанном файле тоже роняет тест; убрал обращение — уменьши число или удали строку.
- **Чего тест не видит:** GORM-вызовы с чужой моделью (`tx.Model(&user.User{})`, `Find(&[]project.Project{})`) и SQL, собранный из кусков (`"… FROM " + table`, `fmt.Sprintf`). Правило на них распространяется так же. Текст лога или ошибки, который тест принял за SQL, переформулируйте, а не добавляйте в список.

## Команды

Только через Makefile из корня репозитория (Go в контейнере):

```
make build      go build → api/bin/taskflow
make test       go test ./... -count=1
make lint       golangci-lint v2
make fmt        gofmt -w
make swag       Swagger 2.0 из аннотаций → internal/docs, UI на /api/docs
make migrate-new name=create_users
```

## Правила кода

- Стандартная библиотека прежде всего: `log/slog` для логов, `net/http` типы, `time` с `time.LoadLocation` (tzdata в образе есть). Новая зависимость — только если без неё заметно хуже; обосновать в PR.
- GORM: без `AutoMigrate`, без `Preload` в циклах. Отчёты, берндаун, курсорная пагинация и всё с `FOR UPDATE` — на чистом SQL через `db.Raw`/`db.Exec`. Транзакция — `db.Transaction`, в ней же запись в outbox.
- Валидация входных данных — binding-теги Gin на структурах запроса; ограничения брать из таблиц §3 (длины, диапазоны, перечисления). Ошибка валидации → 400 с полем и причиной в `details`.
- Ошибки доменного слоя — типизированные (`ErrInvalidTransition`, `ErrTaskAlreadyTaken` …), HTTP-слой маппит их на коды §9.3. Новый код ошибки сначала добавляется в ТЗ §9.3.
- Права: middleware по таблице §2 на уровне маршрута плюс проверка в сервисе там, где право зависит от данных (исполнитель, автор). Пользователь без роли в проекте получает 404, не 403.
- Время: в базе UTC, границы дня и «сегодня» считаются по часовому поясу пользователя (записи времени, таймер) или проекта (сводки, снимки спринта, просрочка) — какой именно, написано в ТЗ у каждого правила.
- Swag-аннотации обязательны на каждом обработчике; `make swag` входит в PR, если менялся API.

## Тесты

- Интеграционные тесты на PostgreSQL и Redis из testcontainers; хелпер поднимает контейнеры один раз на пакет и накатывает миграции.
- Таблично: переходы статусов §4, парсер длительности §6.1, права §2.
- Гонки проверять настоящей конкурентностью (горутины + `sync.WaitGroup`), не мьютексами в тесте.
- Тест, зависящий от времени, получает `clock` через интерфейс, а не вызывает `time.Now()` в коде.
